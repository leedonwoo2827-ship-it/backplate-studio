# 원고를 보내실 때 — 분량을 같이 알려 주세요

원고를 써서 이 앱으로 넘기는 쪽(작가 에이전트)에 그대로 전하는 글이다.

---

## 왜 필요한가

이 원고의 `data-say` 가 **그대로 강의 내레이션이 된다.** 그런데 지금은 다 만들고
음성을 구운 뒤에야 길이를 알게 되어, 짧으면 처음부터 다시 해야 한다.

20장이 그랬다 — 6분짜리로 나와서 되돌렸다.

## 보내실 때 한 줄

```
data-say 합계 6,249자 · 약 19분
```

글자 수는 **공백을 뺀** 수다. 분 환산은 이렇게 한다.

```
분 = 공백 뺀 글자 수 ÷ 5.5 ÷ 60
```

실측값이다 — voicewright F2 기준 초당 5.47자, 19장을 22.8분으로 구워 확인했다.

```
5,000자 = 약 15분
6,600자 = 약 20분
```

## 목표

한 장(챕터)당 **15분 이상 20분 이하.**
→ 공백 뺀 `data-say` 합계 **5,000 ~ 6,600자**

이 범위를 벗어나면 **보내기 전에 알려 달라.** 늘리거나 줄이는 것은 원고 단계에서
하는 편이 훨씬 싸다 — 뒤에서는 그림·음성·영상을 전부 다시 만들어야 한다.

## 한 가지 더

`data-say` 가 비어 있는 장은 앱이 짧게 지어낸다. 표지와 마무리는 앱이 고정 문구를
넣으니 비워 두어도 되지만, **그 밖의 장은 반드시 채워야 한다.**

`data-img`(그림 지시문)는 넣지 않아도 된다 — 앱이 무시하고 새로 쓴다. 그것은
「글자 없는 삽화」 전제로 영어로 쓰인 것이라, 지금 필요한 「글이 박힌 한 판」과
정반대다(`pipeline/s3a_imgprompt.py` 주석 참고).

## 요약

```
보내실 때   「N장 · data-say 공백제외 N자 · 약 N분」 한 줄
목표        15~20분 (5,000~6,600자)
```

---

## ★ 왜 5.5 로 나누는가 — 앱 쪽 사람이 알아 둘 것

앱의 기본 추정값(`narration.chars_per_sec`)은 **3.0** 이다. 실제의 절반쯤이라
음성을 굽기 전에는 길이가 짧게 보인다 — 20장이 12분으로 보였던 이유다.

음성을 한 번 구우면 실측으로 보정된다(`s10_tts._calibrate`). 19장은 5.44 로
잡혔고 실측이 5.47 이었으니 보정은 정확하다. 다만 **첫 판에서는 보정이 없다.**

그래서 원고 쪽에서 5.5 로 미리 세어 주면 그 오차가 없어진다.
