# 핵심 개념

왜 이렇게 만들었나. 고치기 전에 읽을 것.

### 화면은 여섯 — 순서가 곧 규칙이다

```
새 발표   좌표(레포·영상·사이트·참고자료) → 설문 → 기획서
현황판    무엇이 남았나 · 모든 단계 실행          ← 위층(패널)
목차      장 순서·제목·유형 확정 · 빈 장 끼우기 · JSON 입출력
초안      판단·문구·대본을 한 번에 → 전체를 한 판에 놓고 읽는다
수정 유형  슬라이드 텍스트 / +삽입 이미지 / +삽입 영상
덱        음성 · 자막 · 전체 · 굽기
```

**넓게 잡고 좁혀 들어간다.** 목차로 뼈대를, 초안으로 살을 한 번에 붙이고,
전체를 읽으며 고칠 곳만 골라 유형 화면으로 들어간다. 마지막에 덱에서 겉을
돌린다. 장 하나씩 완성해 나가면 25장에 75번을 눌러야 하고, 무엇보다
**나란히 놓고서야 보이는 것**(중복·빈 곳·흐름)을 영영 못 본다.

**목차가 앞인 것이 핵심이다.** 목차는 지금 고치면 공짜고, 확정한 뒤에 고치면
문구·판단·대본·음성을 전부 다시 돌려야 한다. 그래서 비싼 단계로 내려가기 전에
문을 하나 둔다.

### 원고 JSON — **파일은 한 종류다**

칸은 언제나 다 있고, 아직 안 만든 것은 **빈 문자열**이다. 그래서 세 가지 쓰임이
같은 파일 하나로 된다:

```
빈 틀만 뽑아 밖에서 채워 오기      목차 화면에서 내보내기 → 대본 칸이 비어 있음
다 만든 뒤 고쳐 오기               초안 화면에서 내보내기 → 다 차 있음
발표를 통째로 되살리기             11_완성/<slug>-원고.json
```

넣는 곳도 아무 데나 된다 — **파일에 무엇이 들었는지는 앱이 본다.** 대본이 하나라도
들어 있으면 통째로 넣고, 뼈대뿐이면 화면에 올려 보고 확정하게 둔다.

```jsonc
{ "deck_title": "…",
  "sections": [{ "id": "personal", "title": "개인(전문가) 회원 화면" }],
  "slides": [{
    "no": 4, "section": "personal", "kind": "feature", "media_kind": "text_image",
    "title": "내 경력이 어디까지 왔는지 한 화면에서 볼 수 있습니다",
    "note": "", "video_id": null, "evidence_hint": "",
    "body": "경력 건수·프로젝트·증빙 서류 상태에 역량 링 차트까지.",
    "narration": {
      "srt_text": "개인 대시보드입니다. 위쪽에 …",   // 화면 자막(원문)
      "text":     "개인 대시보드입니다. 위쪽에 …"    // TTS 가 읽는 것(발음)
    }
  }] }
```

`narration.text` 는 발음 교정본이다 — `ODA` 를 `오디에이` 로 적어 두면 그렇게
읽는다. 비우면 `srt_text` 를 그대로 읽는다. 길이는 글자수에서 추정하고, 합성이
끝나면 실측으로 다시 잡힌다. `media_kind` 는 `text · text_image · video · code`
넷뿐이고 모르는 값은 `text` 로 내려앉는다. 번호는 무시하고 순서대로 다시 매긴다.

**크기는 걱정하지 않아도 된다.** 40장짜리가 46KB — 장당 1.2KB다. 텍스트뿐이라
음성·이미지는 안 들어간다.

**넣으면 손편집은 버려진다.** 손편집 키는 옛 번호를 가리키는데 번호가 통째로
바뀌므로, 남겨 두면 엉뚱한 장에 옛 자막이 붙는다.

### 하나의 연속 번호, 레인은 섞인다

```
S2b   번호 + 레인 배정      1 텍스트 · 2 영상 · 3 텍스트+그림 · 4 텍스트 · 5 영상 …
  ↓   레인별로 따로 채움    S3 캡션 · S3b 그림 · S5 판단 · S6 대본
S8    번호순으로 다시 모음
  ↓
S9    하나로 렌더링         1 … 37
```

레인이 존재하는 이유는 **만드는 비용이 다르기 때문**입니다. 텍스트는 쉽고, 영상과
그림은 오래 걸립니다. 그래서 따로 만들고 번호로 합칩니다.

레인이 연속 구간으로 뭉치면 발표가 지루해집니다 — 코드가 뭉침을 검사해 경고합니다.

### 세 가지 텍스트는 서로 다르다

| | 무엇 | 만드는 곳 |
|---|---|---|
| 슬라이드 문구 | 화면에 박히는 글 | S7 (문체 선택 가능) |
| 자막 `srt_text` | 입으로 말하는 것의 원문 | S6 |
| 발음 `narration_text` | TTS 가 소리 내는 표기 | S6 |

`2vCPU` 는 자막엔 그대로 두고 발음만 `투 브이씨피유` 로 바꿉니다.

### 승인 게이트 3단

```
1차 화면   슬라이드 면이 이대로 나가도 되는가
2차 대본   자막·발음이 이대로 읽혀도 되는가
3차 무음   (영상 장만) 원본 소리를 죽이고 내레이션만 얹어도 되는가
```

37장을 한 번에 다 볼 수 없으므로 어디까지 봤는지가 파일에 남습니다.

### 손편집이 항상 이깁니다

`10_덱/deck.overrides.json` 이 스테이지 결과 **위에** 얹힙니다. S5·S6·S7 를 다시
돌려도 손으로 고친 자막·문구·✓ 는 살아남습니다.

### 여러 버전

같은 재료로 광고체 한 벌, 개조식 한 벌을 만들어 두고 비교할 수 있습니다.
버전 = 스테이지 캐시 + 손편집 한 벌. 원본(영상·레포)은 복사하지 않습니다.
되돌리기 전에 지금 것을 자동으로 한 벌 뜹니다.

### 기획서는 양방향

처음에는 툴이 `00_기획/prd.md` 를 만들어 줍니다. 익숙해지면 그 파일을 직접 써서
넣으면 됩니다 — 고쳐 두면 다음 실행에서 **고친 내용이 이깁니다.** 코드 변경 없이
접점이 파일 하나입니다.
